## 关键发现与修正

### 高优先级：产品差异被收得过深

当前方案把选择理由和第二轮变化主要放进详情，三步卡片可能只呈现为数据分析流水线。PRD 的核心是履历影响分工，因此任务入口简洁的同时，推荐产生后必须在角色卡直接显示一条有依据的选择理由，并提供候选入口。四个 Agent 的真实可用/候选状态可在简短候选行呈现，不能只留下三位执行者、让待命者消失。

修正：开始前不伪造推荐；推荐后显示候选与实际执行者的区别，第二轮提供主区域内的变化摘要。没有历史时说明按初始规则分配。摘要不能承诺最优选择、自动学习或质量提升。

### 高优先级：单条详情与跨轮比较共用窄抽屉

约 400px 抽屉适合单个 Agent、单次交接或交易详情，不适合两轮、多候选、多个分项的同时比较。强行复用会产生横向滚动和反复切换。

修正：单条内容保留抽屉；“比较两轮分工”进入工作台内全宽比较区域，替换当前主要内容，保留运行摘要和返回入口。按业务角色比较，选定两次真实决策，展示候选、相关履历、负载与所用区块快照。若只能读取一轮，说明缺少另一轮并禁用比较，不补造记录。抽屉内部不再打开第二层抽屉。

### 高优先级：任务、交易和交接状态容易混淆

一个笼统的“运行中/完成”不足以解释角色已生成文件、验收已通过、交易未确认等组合。一个全站绿色状态也不能证明 Worker、任务服务与链同时可用。

修正：业务步骤保持 B 定义的状态，交易与交接独立呈现。待确认时显示具体等待对象及最后更新时间。连接断开使用“状态暂未更新”，不能推断 Agent 已终止。全站状态提供分项详情，没有数据时显示未知，不将空值当正常。

### 高优先级：只禁用执行会让访客没有下一步

没有执行权限、Worker 离线、服务断线、暂无历史属于不同情况。统一灰掉按钮会使用户不清楚能做什么。

修正：访客优先查看真实历史；授权且条件齐备时才能开始。开始不可用时在按钮附近说明原因，输入预览和能读取的历史保持可操作；权限尚未核实时不短暂出现可执行按钮。不另造未获支持的登录或授权流程。

### 中优先级：收起任务卡可能造成布局跳变

由大任务卡直接切换三角色卡片，可能让点击目标、阅读位置或焦点突然移动。报告到达后自动改变布局也有同类风险。

修正：工作台标题、输入摘要与状态位置保持稳定；开始按钮就地进入请求中状态，成功绑定 runId 后再展开流程。保留选择的输入与运行地址。报告插入预留的成果区域，不自动滚动。正在阅读历史或详情时不自动切换最新运行。

### 中优先级：紫色同时代表执行、选中和焦点

当前配色方向合理，但仅变成紫色无法说明当前查看对象还是正在执行的对象。

修正：主按钮用实色紫；选中对象用轻底色与边界；键盘焦点用独立可见外轮廓；实际执行、成功、等待、失败都带图标与文字。状态颜色只用于标记和少量强调，正文保持灰白。原型初值为成功 #4ADE80、等待 #FBBF24、失败 #FB7185，均用在 #171320 深底上；不是这些官网的官方色值。

本轮按 WCAG 相对亮度公式复算：白字/#7C3AED 为 5.70:1，次要文字 #B6AEC5/面板为 8.56:1；成功、等待、失败三色/面板分别约 10.48:1、10.93:1、6.78:1；浅紫/面板约 6.71:1。背景与面板仅约 1.08:1，重要控件不能只凭两种底色区分。尚未核对透明度、实际字重、图片背景和完整渲染后的对比度。

### 中优先级：静态执行标记仍需要可信的等待反馈

取消循环光效可以减少噪声，但所有状态完全静止时，用户也可能怀疑页面已卡住。

修正：显示真实开始时间、最近事件及最近成功同步时间；网络请求中的局部加载提示只表示该请求未返回，不表示 Agent 正在思考。交接事件按 eventId 去重后短暂强调一次，不因轮询、刷新、查看历史或第二轮而补演动画。装饰过渡不阻挡点击，不延迟真实结果显示。

### 中优先级：报告区还缺少阅读与追溯的边界

长报告如果也放进窄抽屉，会妨碍阅读。点击数值后若打开另一个运行的最新指标，也会让来源失真。

修正：报告在主内容区阅读；指标追溯打开单条详情，并严格绑定当前 runId、artifactId 与版本。预览或下载显示真实可用性，文件缺失时明确提示；报告未通过验收时可展示实际产物但标明未通过，不标为已验证报告。

## 逐阶段设计健康度与后续验证

1. 首次进入：方向合理，任务操作需在首屏可见；具体换行和空间尚未实测。
2. 预览与发起：待补权限、不可用原因及提交中状态；去重与请求超时对账依赖 B。
3. 执行与交接：三角色结构清楚，需补可见的选择理由、待命候选和独立状态语义。
4. 查看详情：单条详情可用抽屉，待验证键盘、焦点、点击范围和窄窗口。
5. 阅读成果：主区阅读、可追溯设计合理；生成、验收、链上确认必须分开。
6. 查看历史与第二轮比较：必须使用稳定运行标识和全宽比较视图，不能只在窄抽屉切换两份信息。

原型验证覆盖 1440×900 与 1280×800、200% 放大时的重排、键盘进入/关闭抽屉、减少动效、长文本、无权限、无候选、服务断线、待确认、验证失败、文件不可用、重复事件和刷新恢复。未实现的后端行为列为未验证，不用前端定时器模拟通过。

## 结论

品牌、深色紫色和固定三角色流程继续保留。优先强化可见的分工依据、全宽轮次比较、准确状态和明确下一步，随后检验具体画面。当前只完成方案复核与文档记录，尚未产生页面实现或完整视觉验收。
