## 01 / 产品定义与交付边界

**Agent 协作网络：让本次合作产生的证据，成为下一次分工的依据。**

PRD v1.0 · Monad Blitz V3 上海 · 团队 DNF · 2026 年 10 月 17 日。本文是待实现的产品与交付约定，不代表代码或部署已经完成。A、B、C 为三条工作线，启动时由团队填写真实负责人。


### 交付目标

不同运营者的 Agent 以独立节点接入共同任务，按角色能力、已确认履约记录和当前负载分工；交付物连同验收证据写入 Monad，再用于第二轮分工。用户能够查看“为什么选它”和“它交给下一位的内容是什么”。

本场只交付一个固定工作流：把一份合成业务 CSV 整理成可复核的分析报告。保留数据整理、统计分析、报告表达三个业务角色；提供四个 Agent 身份，其中两个竞争数据整理角色。三名开发者与三个业务角色不是一一对应关系。

| 项目决策 | 本场锁定 |
| --- | --- |
| 核心创新验证 | 可核验的角色履历与交接证据，实际进入下一轮分工；不把总分动画当成果。 |
| 网络与标准 | 默认 Monad Testnet，Chain ID 10143；A 在启动时向现场确认测试网是否符合提交要求。ERC-8004 接入不进入关键路径。[S3][S4] |
| 资金范围 | 本场只支付链上 Gas；不托管用户资金，不实现分润、保证金、代币或 x402/MPP。 |
| 运行形态 | 独立 Worker + 共享任务服务 + Monad 履历账本。至少两个独立进程，目标部署在两台设备；共享服务和指定验收方公开可见。 |
| 事实与宣传 | 展示真实模型/工具执行、真实回执与真实失败。自建账本标明应用级协议，不宣称完整 ERC-8004 兼容或全去中心化裁决。 |

## 02 / 用户、场景与完整体验

**首个用户需要的是一份可复核报告；平台展示的是这份报告如何由不同 Agent 合作完成。**


### 目标用户与使用动机

任务发起人希望知道谁在做事、是否有相关履历、出错后从哪里继续。Agent 运营者希望用已完成的工作证明专长，而非只填写能力介绍。现场评委无需学习协议即可追溯分工、交接和结果。


### 固定演示素材

赛中制作一份 30—50 行合成业务 CSV，字段为 record_id、date、category、sales_yuan、orders。允许预先定义的格式问题，如重复行、日期格式不统一；不得含真实商户隐私。提供第二份同结构数据，用于真实第二轮运行。输入、规则和输出版本均可下载。

| 阶段 | 用户看到什么 | 系统必须完成什么 |
| --- | --- | --- |
| 1. 发起任务 | 选择示例数据，查看三角色工作说明，点击开始。 | 绑定输入哈希与验收规则版本；只对获授权的演示用户开放写操作。 |
| 2. 推荐分工 | 展示候选 Agent、相关角色记录、可用状态与推荐原因。 | 过滤能力不匹配或忙碌节点，计算可复现排名，保存信誉区块快照。 |
| 3. 接受工作 | 被选节点确认接单；其余节点保持待命。 | 独立 Worker 确认任务与 attempt；链上指派确认后执行。 |
| 4. 分段交付 | 数据整理 → 统计分析 → 报告表达。 | 下游只使用已验收的上游版本；原始文件、统计结果与报告相互关联。 |
| 5. 写入履历 | 每个角色出现 PASS / FAIL、检查项和区块浏览器入口。 | 验收方提交唯一结果；只有已确认记录参与信誉计算。 |
| 6. 再次组队 | 用第二份数据再次发起，展开“与上次相比”。 | 从链上重新读取角色记录，展示变化的评分、理由和候选排名。 |


### 什么叫真实验收

数据整理：必需字段、类型、去重规则、规范化结果通过固定检查。统计分析：由可信工具重算汇总值，核对模型输出与输入一致。报告表达：输出结构化 claims，每条数值结论引用已确认的指标 ID；图表读取同一份指标数据。自由文字的风格质量由用户判断，不包装成链上证明。

> 路演承诺：第二轮确实读取第一轮链上证据。获选者可以不变，分数和依据必须可复算；不得硬编码“第二轮一定换人”。

## 04 / 信誉如何真正影响分工

**采用一套能解释、能复算的原型政策；不把手设权重包装成经过实验验证的最优算法。**


### 信誉来源与范围

只读取本场应用账本、指定验收方确认的记录。按 agentId + role 分开统计 PASS 与 FAIL；UNRESOLVED、RPC 超时、未确认交易和被取消任务不进入质量分母。结果文件损坏、验证节点失联先停在等待状态。角色信誉不跨领域通用。

每条记录绑定 taskId、attempt、assignee、role、criteriaHash、artifactHash 与验收证据。合约拒绝同一 attempt 的重复结论。运营者自称能力只能用于初步资格筛选，不能直接加信誉分。


### 分工政策 role-rep-v1

| 步骤 | 固定规则 |
| --- | --- |
| 资格过滤 | 角色匹配；Heartbeat 距今不超过 30 秒；空闲槽位至少一个；节点已加入本场准入列表并确认接单条件。 |
| 角色信誉 R | R = (PASS + 1) / (PASS + FAIL + 2)。无历史时为 0.5；同时展示样本量，不把 0.5 称为真实成功概率。 |
| 可用度 A | A = 1 - activeTasks / maxConcurrency，范围 0—1。默认 maxConcurrency = 1；在线状态来自运行时，不来自链上旧记录。 |
| 综合排序 | score = 0.8 × R + 0.2 × A。能力先过滤，再评分；同分按 agentId 稳定排序，避免随机演示。 |
| 决策冻结 | 每次决策保存 policyVersion、repBlockNumber、候选集合、所有分项、排除原因和选中者；任务中途不悄悄换规则。 |
| 冷启动 | 新节点允许参与固定低风险模板，与所有零历史节点使用同一先验；本场不声称解决身份刷分或市场公平性。 |


### 可复算示例：这些数值是政策示例，不能写入真实履历

节点甲完成一笔有效工作后，R 为 2/3；节点乙尚无履历，R 为 1/2。两者都空闲时，score 分别约 0.733 和 0.600。若甲已无空闲槽位，先被资格过滤；乙可以接单。这说明履历与实时负载分别发挥作用。


### 协作证据怎么使用

交接记录保留上游版本、下游要求、接收或退回理由，并进入验收证据文件。本场不再引入一套伙伴图评分或贝叶斯模型。相同输入和相同快照必须得出相同排序；已有证据不足以改变名次时，页面展示分值及理由变化即可。

> 去中心化信誉的事实边界：链上保存谁作出什么判断及其证据摘要；结果质量仍依赖公开指定的验收方。ERC-8004 同样区分反馈接口与应用聚合政策。[S4]


## 05 / 系统边界与任务状态

**链上负责可验证的身份、指派与履约记录；链下负责工作本身、文件可用性和交互。**

| 组件 | 责任 | 写入边界 |
| --- | --- | --- |
| 链上履历账本 | 身份、任务指派、产物承诺、验收结论、按角色统计与事件。 | Agent 只能提交自己当前 attempt；指派由授权协调者提出，验收由预设验收方完成。 |
| 任务与发现服务 | 固定模板、候选排名、节点状态、任务领取通知、持久化事件与文件目录。 | 服务可协调任务，不能伪造 Worker 的链上提交或任意改写历史分数。 |
| 独立 Worker | 持有自己的签名密钥和模型凭证，接受指派、执行工具/模型、交付产物。 | 通过共享服务发现工作；链上交易由各自签名地址提交。支持独立启停。 |
| 验收服务 | 重算固定检查、生成证据文件、提交 PASS/FAIL。 | 身份与权限可查询；不接受被评 Agent 的自评作为唯一证据。 |
| Web 工作台 | 任务、拓扑、候选解释、成果、信誉和回执展示。 | 只读公开；触发任务等管理动作需演示授权，不暴露私钥或模型密钥。 |


### 状态约定

任务主线：OPEN → ASSIGNED → RUNNING → SUBMITTED → VERIFIED_PASS / VERIFIED_FAIL。运行时的 RUNNING 表示节点确认执行；链上可以保留 ASSIGNED，界面标注来源。每个终态只产生一条质量记录。

交易状态独立为 PENDING / CONFIRMED / FAILED。产物已生成但回执未确认时，显示“结果就绪，履历待上链”，不能先增加信誉。待确认或回执未知时，A 先对账同一交易；B 不能生成新的业务结果重复记账。

交接状态为 PENDING / ACCEPTED / RETURNED。下游只接受哈希相同、schema 合格且上游已通过验收的产物。退回说明先进入证据文件，不能由下游一次拒绝直接扣上游信誉。

P1 接续：已指派任务超过固定租期且没有有效产物时，可显式 expire；新指派的 attempt 递增。旧 Worker 的迟到提交必须被拒绝。超时记录与质量失败分开，重派不重复生成已有上游任务。


### 对外描述

本场展示“分布式 Agent 执行 + Monad 共享履历账本 + 可解释分工”。任务发现与验收仍由明确组件承担；不宣称去中心化共识评判模型输出，也不宣称没有任何中心服务。


## 06 / 三线共享接口：14:45 冻结

**B 维护业务类型；A 维护链上 ABI 与读写适配；C 只消费接口，不自行定义第二套状态。**

| 对象 | 必须一致的字段 |
| --- | --- |
| AgentProfile | agentId（签名地址）、roles、manifestURI、manifestHash、runtimeId、lastSeenAt、activeTasks、maxConcurrency。 |
| Run / Task | runId、taskId、role、dependsOn、attempt、assignee、inputHash、criteriaHash、status、validator。taskId 使用固定派生规则。 |
| AssignmentDecision | decisionId、taskId、attempt、policyVersion、repBlockNumber、candidateScores、excludedReasons、selectedAgentId、decisionHash。 |
| Artifact / Handoff | artifactId、taskId、attempt、parentArtifactIds、URI、contentHash、schemaVersion、producer；交接带 fromTaskId、toTaskId、status、reason。 |
| Assessment | taskId、attempt、verdict、checks、evidenceURI、evidenceHash、validator、receipt；UNRESOLVED 仅为等待，不计入链上质量记录。 |
| ChainReceipt / Event | chainId、contract、txHash、blockNumber、status；事件带 eventId、seq、runId、taskId、attempt、type、createdAt。 |


### A → B/C：链上业务端口

registerAgent；assignTask；submitArtifact；recordOutcome；getRoleReputation；getTask；getReceipts。P1 才增加 expire/reassign。每次指派绑定角色、规则、输入和 attempt；Worker 仅能提交自己被指派的工作；评审结果由固定验收地址签名。

A 交付 ABI、部署地址、起始区块、链 ID、浏览器前缀、角色枚举、错误码及 TypeScript 适配器。只交付合约源码不算完成。getRoleReputation 必须支持指定快照区块读取或从已确认事件重建。


### B → C / Worker：HTTP 接口

工作台：GET /api/agents；POST /api/runs；GET /api/runs/:id；GET /api/runs/:id/events?after=seq；GET /api/artifacts/:id。页面每 2 秒增量轮询，刷新可恢复，不把 WebSocket 作为依赖。

Worker：POST /worker/heartbeat；GET /worker/jobs；POST /worker/tasks/:id/accept；POST /worker/artifacts；POST /worker/tasks/:id/submit。Worker 端点使用独立节点凭证；submit 携带真实提交回执，由服务核对 signer、taskId、attempt 和产物哈希。


### 共同约束

哈希统一为对持久化原始 UTF-8 文件字节做 keccak256；禁止各端重新序列化后得到不同摘要。业务键为 taskId + attempt，事件按 seq 去重。统一错误码：WRONG_CHAIN、UNAUTHORIZED、STALE_ATTEMPT、DUPLICATE_OUTCOME、ARTIFACT_MISMATCH、CHAIN_PENDING。

> 开发夹具可以用于并行联调，必须标记 DEV_FIXTURE；公开提交默认 LIVE。REPLAY 只能回放已保存的真实运行，不能伪造交易、履历或执行结果。


## 07 / 前端与路演体验

**主页面只围绕一个目标：让观众在一分钟内看懂谁接了哪份工作、为什么是它、留下了什么证据。**

| 区域 | 显示内容 | 必须交互 |
| --- | --- | --- |
| 顶部任务栏 | 输入文件、模板版本、运行状态、LIVE/REPLAY、网络与节点在线情况。 | 创建演示任务、查看输入、重新运行第二轮；正在执行时防重复点击。 |
| 中央协作图 | 三个业务角色，候选与实际执行节点；边代表具体交接，状态由真实事件驱动。 | 点节点打开 Agent 履历；点边打开上游产物、下游要求与接收理由。 |
| 右侧分工依据 | 候选评分、PASS/FAIL 样本数、负载、排除原因、读取区块和政策版本。 | 比较第二轮与历史快照；允许结果不换人，但清楚展示数据变化。 |
| 底部证据流 | 任务指派、提交、验收、链上回执；明确等待、确认、失败。 | 打开 Explorer、证据 JSON、结果文件；刷新页面后记录仍在。 |
| 成果抽屉 | 规范化数据、汇总指标、图表、结构化报告。 | 下载成果与引用来源；显示数据为赛中生成的合成示例。 |


### 三分钟演示脚本

0:00—0:25：提出问题——不同人的 Agent 合作时，谁适合这份工作，不能只看一句自我介绍。展示四个节点与固定任务。

0:25—1:15：创建任务，展示候选原因和三个角色的交付。耗时较长时，打开已完成的真实 LIVE 记录，明确标记这是保存的运行，不伪装即时结果。

1:15—2:10：点开一条交接、一份验收和对应链上回执；说明此记录只影响相应角色的履历。

2:10—2:45：发起第二轮或回放刚刚完成的第二轮，比较相同政策下的信誉快照与推荐理由。解释新记录如何进入分工。

2:45—3:00：总结——这次合作留下的履历，下次真的用得上。P1 接续演示只在已验证时附加，不挤占主线。


### 可用性与可访问性目标

桌面 1440×900 为主，笔记本可用；状态除颜色外必须有文字。普通读取不要求连接钱包。公开结果页在 Worker 下线后仍可查看，在线执行入口则明确显示实际运行条件。所有目标均待团队实测。


## 08 / 三份工：所有权、交接物与责任

**团队每人只接一条主线；每条线拥有自己的测试与交付证据，不把“集成”留给无人负责的最后一小时。**

### 人和 Agent 的分工不同

B 编写通用 Worker。A 与 C 各运行一个实例，B 运行其余角色，因此至少两台可用设备能实际参与同一任务；做不到两台时如实标注多进程演示，不把钱包数量当作独立运营者证明。


### 集成规则

分支命名 work/a-ledger、work/b-runtime、work/c-web；C 是内部集成负责人。B 独占业务 schema 变更，A 独占 ABI/链配置变更。根 package.json 与锁文件由 C 合并维护，其他人提供依赖请求，避免三个 Agent 同时改锁文件。

每次交付必须含：提交哈希、启动方式、最小成功案例、已知失败项、下一条线可以直接调用的接口。交接后接收人实际调用一次；“已推送”不等于“已接通”。14:45 后仅允许向后兼容新增字段，破坏性变更需 C 协调三线同时更新。


### MOJO 责任

已确认用户加入 DNF 团队；现有队长身份与其他成员不在已读取信息中。C 负责材料和核对，MOJO 最终提交必须由现有队长完成。不要默认 C 或用户本人就是队长；14:45 前在现场点名确认。

> 每个时间门只回答四件事：能打开什么、刚验证了什么、被什么阻塞、下一次交接是什么。超过 10 分钟无进展就暴露阻塞，不另开大方案。

### 部署约定

C 部署静态前端或 Web 应用；B 部署常驻任务服务与 Worker，并使用持久存储保存运行、文件和事件。不要把无限轮询 Worker 放进短生命周期请求处理器。至少一个 Worker 和只读结果服务必须在团队离场后继续运行。

14:45 前明确实际可用的托管账户、常驻进程位置、持久存储和费用承担者；C 只填写已获授权的账户配置。本 PRD 不代表已获得任何云资源。团队以至少 7 天可访问为维护目标，官方规则只要求长时间有效，未在所给规则中规定具体天数。[S0]

### 密钥与运行安全

每个 Worker 使用独立测试钱包；私钥、助记词、模型密钥只放本地或服务端密钥配置，绝不进入仓库、浏览器构建、录屏或截图。工作流只允许固定数据模板与预定义工具，禁止任意 shell、任意外部 URL 和未审查模型代码执行。

公开页面默认只读。新建任务需要演示授权，Worker 接口需要节点凭证并核对实际签名者。模型调用设总量和并发上限。可信验收方只是本场准入和裁决配置，不标称无许可信誉网络。

### 项目差异的判定

往届 AntForge 已描述技能匹配、工作提交、验收和链上结算，并在提交页标注 Agent 产物采用确定性模拟。[S5] 本项目不以“多 Agent + 链”为首创主张；用真实独立节点、可审查交接、链上履历回读和第二轮可复算分工表达差异。是否改善任务质量，需要后续实验，比赛演示只证明流程确实发生。


### 标准选择

ERC-8004 当前为草案，区分身份、信誉与验证登记，并把付款置于范围之外。[S4] 本场的自建账本只承诺本文列出的角色履历与验收接口；外部标准地址、身份引用与反馈写入只有实际验收后才能标记已接入。用户提供的 monskills 可作为开发指南，执行安装前确认依赖并在赛时进行，不要求为使用 Skill 而复制已有应用。
