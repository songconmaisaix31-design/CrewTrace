# CrewTrace 产品战略：Trust、Coordination、Commerce

## 定位

CrewTrace 的方向是 Agent 经济中的去中心化信任基础设施。核心价值有三项：可验证履约、Agent 信誉、以及由信誉驱动的决策。当前产品是原 CrewTrace 可信协作网络的增量增强版，参赛赛道为 PAYATHON 的 Machine Pay。CSV 清洗是标准化实验场景，支付宝是商业化验证渠道，Cloudflare 是部署基础设施。这三项都是当前验证手段，不改变产品定位。

本文件描述长期方向。三阶段关系用于解释已有能力与后续研究的关系，不构成本轮或下一轮的直接开发任务。

## Trust：可信协作与信誉记录

第一阶段解决“这次交付是否被验收、由谁验收、能否被机器读取”。团队版本已经建立了 Agent 身份与私密凭证、公开任务、提议、认领、交接、验收、消息、便签、公告、事件与链上承诺，并把任务、提议、认领、交接写入 Monad Testnet。信誉按角色计算，公式为 `(PASS+1)/(PASS+FAIL+2)`，无历史时为 0.5，在同一 finalized 区块读取。原团队合约 `AgentLedger.sol` 与 `CollaborationLedger.sol`、viem 适配器与部署记录在本仓库完整保留。

这一层已经实现并有本地与测试网记录，当前公网运行环境未配置链上写入，因此链上部分处于“代码与合约就绪、运行未启用”的状态。

## Coordination：信誉驱动的调度与确定性验证

第二阶段解决“下一轮任务派给谁、交付是否可复算”。个人扩展在团队协作模型之上增加了版本化 CSV 校验、按角色信誉事件、PostgreSQL 自动调度、Worker 准入与心跳、有限重试、租约恢复、指派快照、独立 CSV Worker、历史与证据回放、策略基准。调度使用上一次被验收的交付形成的信誉快照，验证使用确定性规则而不是模型判断，交接被验收后一次性写入信誉事件。

这一层已经实现并经过本地真实 Worker 与真实数据库验证，属于当前 Beta 的实验能力。它依赖单一固定流程与三角色白名单，模型 Worker、任意工作流图、去中心化争议处理与信誉申诉仍未实现。

## Commerce：Machine Pay 商业交易与可信履约

第三阶段解决“Agent 之间如何为一次可验证的履约完成付款”。PAYATHON 增量提供标准服务目录、订单、报价快照、支付宝预下单与验付接口、交付下载、买家验收以及订单与信誉的关联，MCP 增加 8 个服务与订单工具。收费订单在支付未配置时返回 `PAYMENT_NOT_CONFIGURED`，公网保持 `PAYMENT_MODE=disabled`，免费服务可完整体验。

这一层已实现接口与状态机，尚未完成 Machine Pay 官方联调与真实资金交易。支付宝是商业化验证渠道，不改变“可信履约与信誉”这一产品核心。

## 三阶段关系

Trust 提供可被机器读取的履约记录与信誉来源，Coordination 用这些信誉做调度决策并用确定性规则验证交付，Commerce 把可验证的履约接入商业交易。Commerce 的可信度来自前两层：订单完成状态由验收结果决定，验收结果写入信誉，信誉影响后续指派。

跨平台、可核验的 Agent 信誉基础设施是长期探索方向，包括跨平台身份映射、可移植的信誉凭证、第三方可复算的履约证明与争议处理。这些内容属于研究议题，当前没有实现计划，也不作为本轮任务的验收要求。

## 已实现、实验与未来研究

已实现并有运行记录：团队协作模型与 Web 工作台、MCP 53 个工具（公网按权限展示 42 个）、Agent 身份与凭证、任务、提议、认领、交接、验收、消息与便签、链上承诺代码与 Monad 合约、固定 CSV 三角色流程、三个 Worker 的本地运行、免费服务订单全链路、信誉事件写入。

实验能力：PostgreSQL 自动调度与指派快照、租约恢复与重试、证据回放、策略基准、订单与信誉关联、公网 Pages Function 代理与权限收敛。这些能力已在本地真实环境验证，尚未在稳定公网后端上长期运行。

未来研究：Machine Pay 官方联调后的真实付款、跨平台信誉互操作、可移植信誉凭证、争议处理与信誉申诉、多模型 Worker、任意工作流编排。

长期方向不转化为本轮开发任务。本轮只做冻结、兼容性核对与文档化。
