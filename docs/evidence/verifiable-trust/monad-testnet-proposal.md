# Monad Testnet 后续实验提案

状态：`NOT_DEPLOYED`，等待单独批准。当前仓库没有部署任何公共测试网合约，也没有使用团队私钥或需要真实资金的账户，新增现金支出为零。

## 拟使用网络

Monad Testnet（chain ID 10143）。实验只在测试网进行，不涉及主网、真实资产或生产流量。网络选择原因是 CrewTrace 现有链适配器已支持 EVM 兼容链，测试网能验证公共 RPC、确认延迟与浏览器可见性，同时不产生现金支出。

## 拟使用合约

复用现有 `CollaborationLedger` 合约源码，不新增合约类型，不改动合约接口。每个实验环境部署一份新实例，`recorder` 构造参数设为独立实验记录账户。合约只保存 `kind`、`recordId`、`version`、`contentHash` 与 `uri`，不保存凭证正文、交付内容、主体身份或信誉数据。

## 拟使用账户

- 部署账户：新建的一次性测试网账户，只领取公开水龙头测试币，不导入任何团队或商业分支私钥。
- 记录账户：另一个新建的一次性测试网账户，作为合约 `recorder`，只用于写入实验承诺。
- 签发账户：两个受控实验签发密钥对，仅在本机生成并保存，不用于任何真实资产。
- 验证账户：只读 RPC 调用，不需要私钥。

全部账户在实验结束后公开说明用途和废弃状态。禁止使用团队私钥、支付宝商业化分支账户或任何需要真实资金的账户。

## 公开字段

链上公开可见的字段限定为 `kind`、`recordId`、`version`、`contentHash`、`uri`、`recorder`、区块号与交易哈希。`recordId` 由凭证标识派生，`contentHash` 为凭证摘要，`uri` 使用 `urn:ct:attestation:<attestationId>`。这些字段不包含 CSV 内容、代码内容、主体身份、信誉事件或任何个人数据。凭证正文仍保存在链下，由持有者自行提供。

## 费用来源

只使用 Monad Testnet 水龙头发放的测试币。不购买测试币，不支付法币，不使用主网资产，不设置任何需要真实资金的账户。新增现金支出为零。如果水龙头不可用或测试币不足，实验停止并保持 `NOT_DEPLOYED` 状态。

## 外部核验需求

- 独立验证者不依赖记录者本地数据库，直接通过公共 RPC 读取合约存储与事件。
- 记录者、签发者与验证者的角色必须分开，验证者只信任自己配置的记录账户与签发名单。
- 需要至少一次跨进程或跨机器的独立回读，证明链上承诺不是本地模拟。
- 需要检查签发者与记录者的区别，以及未授权签发者和未授权记录者都不能通过信任策略。
- 需要记录至少一次凭证撤销后历史链上承诺仍然存在但被策略拒绝的结果。
- 需要比较签名凭证摘要与链上承诺摘要，确认内容变化会被检测。
- 需要公开 RPC 端点、合约地址、交易哈希与区块号，便于第三方复核。

## 测试验收标准

1. 两个签发主体的凭证分别写入链上承诺，交易成功且事件可读。
2. 独立验证者在另一进程通过公共 RPC 回读两份承诺，`chainCommitment` 为 `PRESENT_MATCH`。
3. 未授权签发者的凭证即使有链上承诺，验证结果为 `REJECTED` 且 `issuer` 为 `UNKNOWN`。
4. 未授权记录账户不能写入；验证方配置错误记录账户时得到 `CHAIN_RECORDER_UNAUTHORIZED`。
5. 撤销某凭证后，链上历史承诺仍可读，验证结果为 `REJECTED` 且 `revocation` 为 `REVOKED`。
6. 修改签发凭证内容并重签后，链上核验返回 `PRESENT_MISMATCH`。
7. 所有测试绑定准确提交 SHA，并在 GitHub CI 之外单独保存公共 RPC 回读记录。
8. 实验结束后提交公开报告，说明网络、合约、账户、公开字段、费用来源、实际交易与剩余信任边界。

## 必要性判断

本地 Hardhat 实验已经能验证签发者、记录者、凭证摘要与链上承诺的关系，也能验证撤销、未授权记录者与内容差异。公共测试网能额外验证的是公共 RPC 可用性、跨机器独立回读、浏览器可见性与网络确认行为。这些属于部署与可达性验证，不改变信任模型本身。只有在需要向外部开发者证明“链上承诺可由第三方在公共网络独立回读”时，测试网实验才具有明确必要性；如果本地实验已经足够支撑当前受控试用，则不应仅为了增加链上功能而部署。

本提案等待单独批准。未获批准前不部署、不申请测试币、不创建公共账户。
