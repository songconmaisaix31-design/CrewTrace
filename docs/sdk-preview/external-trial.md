# 外部试用说明与反馈模板

## 当前状态

截至本版本，没有真实外部开发者完成试用，也没有第三方组织采用 CrewTrace 信任核心。状态为 `NOT_VALIDATED`。V0.3 已进入开发冻结，试用材料保留用于后续真实需求触发。下面的材料用于邀请受控开发者试用，不代表已经获得客户、评价或市场需求验证。

## 试用前提

- Node.js 24 或更高版本。
- 使用仓库生成的本地 tarball 安装，不发布 npm。
- 自备签发密钥、签发者名单与撤销列表；SDK 不内置信任根。
- 不连接 CrewTrace 数据库，不启动原 Web、Runtime 或 Worker。
- 代码任务只使用受控合成样本；不要提交真实业务代码或敏感数据。

## 建议试用流程

1. 按 15 分钟 Quick Start 安装 SDK 并核验一份 CSV 凭证。
2. 用 `issueCodeAttestation` 签发一份代码任务凭证，用独立审批密钥生成执行授权，再在另一个目录用 `verifyAttestation` 复算。
3. 修改交付文件、测试报告、测试集合或执行授权，确认分别得到 `REJECTED` 与对应 `reasons`。
4. 配置 `recognizedRuleVersions`，确认未列出的规则版本被判为未知。
5. 用 `signTrustConfig` 生成签名信任配置，在另一进程用 `loadTrustConfig` 与独立预置的根公钥加载，再尝试篡改、过期与版本回滚。
6. 用两种任务各一份凭证聚合信誉，确认分桶按任务类型与签发来源隔离。
7. 运行跨 Agent 示例，确认消费者只依赖公开凭证、名单与授权证据。

## 反馈处理约定

反馈只用于判断是否存在明确的接入需求与阻断问题。未确认的需求不进入实现。试用者提供的凭证与证据如包含敏感内容，应在上传前移除或替换。试用反馈不得被改写为第三方客户证言、用户数量或市场结论。
