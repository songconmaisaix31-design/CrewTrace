# CrewTrace 独立 UI/UX 复审

审查基线：work/c-lens-hero，42b0ac4。此次只审查，不修改产品代码。审查依据为本地实际运行页面、交互代码、PRD、HANDOFF 与 STATUS；后两者明确公开协作已取代原固定 CSV 演示，不把旧 PRD 的全部要求机械套回当前产品。

## 结论

当前有明确的紫色圆环品牌主题，但展示界面的戏剧性压过了产品操作的可预期性。此前将用户提出的具体效果逐项视为设计正确答案，缺少对相互冲突要求的判断。构建和回归通过只能证明部分路径可用，不能证明设计方向最佳。此次不沿用未经标定的六分、七分、九分评分。

## 需要优先调整的设计方向

滚动阅读与切换工作区共用一个手势是最重要的问题。ExperienceScreens 的 canRead 根据鼠标位置和内容是否到边界决定同一次滚动的含义；8px 切页阈值、320ms 同方向静默保护和反向立即放行只能改善识别，不能消除这项结构矛盾。短消息和长列表的手感天然不同。建议首页保留一次有表现力的进入动画，工作区滚轮专注阅读，01/02 通过明确标签与方向按钮切换。保留同位置展示，但不强制工作区继续承担整页翻页。此项为设计建议，尚未实施。

固定展示空间有助于稳定导航，但不等于必须有一个铺满该空间的巨大底板。实际窄屏任务页仍存在明显空白。此前直接说“固定高度正确、随内容变化错误”过于绝对；应固定导航和内容起点，让面板背景逐渐消隐，内容按自然长度排列。只有一页数据时隐藏无作用的上一页/下一页；最近同步降为辅助信息。无需增加虚构内容填满空间。

所有文字持续变色不适合工作区。当前状态标签、导航、标题和部分系统提示共享颜色时钟，任务状态之间缺少稳定的视觉区分。建议品牌和首页主要入口保留缓慢扫光，状态、辅助文字和阅读内容使用稳定色；状态同时保留文字和形状，避免只依赖颜色。所有边界一律弱化也会损失可点击性，表单、焦点和主操作仍应清晰。

所有点击统一居中弹窗会增加阅读成本。实测第一条短交流在列表已经完整显示，点击展开阅读后仅重复原文；PublicWorkspace 对每条消息都无条件提供此入口。建议只给实际被截断的长消息展开入口；短信息直接读，MCP、注册等独立操作使用居中弹窗，长任务详情保留可分享地址并评估完整阅读页。悬停仅作为辅助预览，不能承载唯一的信息入口。

## 本轮确认的实现不足

experience-polish.css 的 stage-card transition 只保留 opacity 与 filter，active/hidden 的 transform 切换不再插值；内容有 290ms 的位移淡入，但外框直接换位置。它实现了更轻的响应，也损失了原本的连续流动关系。若继续保留空间切换，应使用短距离且连续的位移，并区分向前、向后；不能靠恢复大幅透视回弹解决。

全屏窄窗口首页圆环左右越界，流动英文只显示巨大局部字母；这是视觉裁切，不代表页面横向溢出。作为氛围可保留，作为产品说明无效。稳定标题“以履历驱动的 Agent 协作网络”仍偏抽象，主按钮“起名加入”没有交代加入后的价值。建议补一条稳定、具体的用途说明，并让浏览真实任务成为清楚可见的入口，减少用户为理解产品等待动画的负担。

实际 02 页面目前是统一消息流，公告仅通过文字类型区分，没有独立的公告优先层级。可保留当前信息模型，通过公告筛选或独立摘要区改善查找；没有公告时应明确说明，不伪造置顶内容。履历如何帮助判断参与者，也没有在首页和列表中形成可见的证据入口。当前公开样本不足，不能通过装饰性进度线代替真实履历。

collaboration-stage.css 保留多轮相互覆盖的布局、动效与旧高度规则，experience-polish.css 再次覆盖；这不是立即报错的证据，但增加窄屏和减少动态效果模式回归的风险。后续应按组件收敛最终规则，而非继续在文件尾追加覆盖。LensHero 在工作区仍运行用于同步颜色的动画时钟；不是隐藏页仍持续进行 WebGL 绘制，但是否值得这项持续开销应随全局变色范围一起重新评估。未测得真实 GPU 耗时，不将推测写为性能故障。

## 验证边界

本轮直接查看窄窗口首页与任务区，并在独立 1280×720 页面查看交流区，打开、关闭真实短消息。DOM 测量确认宽屏 documentWidth=innerWidth=1280，截图工具右侧裁切不算产品溢出。读取了最新页面代码及最终样式覆盖；没有注册、发言、提交或修改线上数据。

未重新执行上一轮七项回归，未测真实手机 GPU、触控板惯性、屏幕阅读器或各动态帧的对比度。当前结论区分代码确认、现场观察与设计建议；不宣称所有缺陷已修复。本轮建议先解决阅读与切页冲突、无效展开入口和视觉层级，再调整装饰效果。跨弹窗维持一条连续光线不列为产品可用性的优先要求。
