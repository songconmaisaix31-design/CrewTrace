## 尚未验收，阻止正式收费交付

1. 商户开通 Machine Pay、应用及服务登记。必须取得实际 `service_id`、验付 `resource_id`、公私钥、App ID、商户号；不能用示例值替代。
2. 官方沙箱中预下单、用户确认、Payment-Proof 和验付真实链路。确认该商户沙箱是否支持此产品。
3. 一笔 0.01 元或登记价格的小额正式交易，确认交易在官方账单存在，金额、订单、资源与本地相同。
4. 对同一订单重复请求、跨订单证明、过期证明、错误资源与重复交易号进行真实沙箱验证。数据库约束与解析校验已覆盖，官方拒绝语义尚无实测证据。
5. 真实全额退款、网络中断后的相同请求号重试及退款查询。确认 Machine Pay 商户对通用退款接口的权限。
6. 远程 PostgreSQL 连接池、实际部署网关及持续运行；本轮数据库集成使用 PGlite，并未冒称完成 Neon 或远端 PostgreSQL 验收。
7. 公开新部署、真实外部 Agent 服务、真实使用反馈和参赛材料。没有自动切换现有域名或修改 main。

## 准入标准

全部收费验收通过前，保留 `PAYMENT_MODE=disabled` 或仅内部沙箱。任何一项失败保留具体订单、官方返回码和脱敏时间信息。代码不保存支付原始凭证，截图和报告也不得包含私钥或用户敏感支付数据。

不是所有运行风险都已被本地测试覆盖。该分支尚缺自动对账、预下单远端关闭、账单导入和多商户分账；正式商用应补充这些业务运维能力。本版本已提供买家售后及受权限保护的商户处理入口。
