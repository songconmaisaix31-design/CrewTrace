# C 线前端设计与审查记录

记录日期：2026-10-17。产品事实来源为仓库 PRD.md；本文区分当前用户已确认的方向和后续审查建议，不替代 B 的接口定义或 A 的链上适配。

## 用户已确认的方向

面向普通用户，以紧凑操作型首页呈现，第一屏同时露出品牌、任务入口和三步协作流程。用户可先理解任务、查看数据，再启动分析或查看已有真实运行。

标题：co-vibe｜以履历驱动的 Agent 协作网络。

副标题：让这次合作的成果，成为下次分工的依据。

说明：连接不同运营者的 Agent，按能力与已验证履历分工，将交付与验收证据记录到 Monad，让每次选择都有据可查。

本次固定工作流为数据整理 → 统计分析 → 报告表达。输入为 PRD 约定的合成业务 CSV 示例，不擅自加入任意任务、自由上传或任意 Agent 工具执行。

开始前提供示例文件预览、预期交付物与任务入口；开始后在同页展开执行过程，任务卡收成摘要。点 Agent 查看履历和分工理由，点交接查看实际产物、验收及接受或退回原因。分工卡先给简短理由，详细计算按需展开。

成果就绪后突出报告、图表和下载入口，执行记录与链上证据可展开。结构化数值结论可追溯到指标与来源文件；不将自由文字质量描述为链上已证明。

第二轮真实读取已确认履历，展示与历史快照相比的变化；执行者可以不变，不预设排名或更换结果。

不同业务 Agent 通过共享任务服务交换结构化消息和成果引用。消息关联 runId、taskId、attempt、角色与产物版本，完整数据保留在成果文件中。下游核对上游验收、哈希及 schema 后继续。此前聊天中的 JSON 仅为沟通示意，不是 B 已冻结的 API。

公开页面以查看为主，启动真实任务需要演示授权。布局和交互可先开发，未连接服务时明确呈现未连接，不以虚构履历、交易或成功记录冒充运行。

视觉采用深色背景、紫色主色；紫色突出主操作、当前步骤和选中对象，状态另配明确文字。参考研究曾读取 Linear、Warp、Raycast 官网内容，未截图验证视觉，也未通过 Firecrawl 采集。

## 已讨论配色及实算结果

背景 #0C0A12，面板 #171320，正文 #F4F1FA，原主色 #8B5CF6，浅紫 #A78BFA。色值是为本项目提出的方案，不是参考网站的官方色值。

按 WCAG 相对亮度公式计算：正文与背景约 17.62:1，正文与面板约 16.35:1；白字与原主色约 4.23:1，白字与浅紫约 2.72:1。后两种组合不能用于要求 4.5:1 的普通字号文字。

本轮原型调整采用主按钮 #7C3AED 搭配白字（约 5.70:1），悬停 #6D28D9 搭配白字（约 7.10:1）。浅紫用于深底链接与焦点。次要文字采用 #B6AEC5，与面板配对约 8.56:1。这些是设计约定，尚未编写样式或验证实际渲染。

面板与背景对比约 1.08:1，建议依靠间距与适当边界组织层次；可操作控件和焦点仍需独立检查。已计算的纯色对比度不能证明最终页面全面无障碍合规。

参考：https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html 。

## 纳入下一版原型的审查要求

- 分别呈现报告生成、验收通过、链上确认；确认条件未全部满足时，不显示整项任务已完成。预览报告时标明当前证据状态。
- 创建成功后绑定固定运行地址，刷新恢复同一任务；创建请求超时先对账，不盲目再次创建。具体去重能力与 B 确认，C 不自行改公共接口。
- 断线保留最后已知状态并显示更新时间；连接恢复后增量读取事件，不重启任务。只在后端实际支持时显示重试或恢复操作。
- 初始突出任务，运行中突出当前步骤，完成后突出报告；不把候选详情和底层证据同时全部展开。
- 为履历和交接提供显式按钮，避免只能点击细线或卡片；详情面板支持关闭、键盘与焦点恢复。
- 自动轮询不抢焦点、不强制滚动、不切换用户选中的历史任务。关键状态使用适当的无障碍状态通知，避免每两秒重复播报。
- 第二轮区分履历、负载、在线状态带来的变化，不能把所有推荐变化都归因于信誉。
- 动效仅响应真实状态；建议交接事件短暂播放一次，执行状态稳定可读。按钮反馈 120—160 毫秒，详情展开 180—240 毫秒作为待实测初值。
- 尊重减少动态效果设置；不用持续粒子、扫描光和循环发光来代表不存在的实时通信。

状态通知参考：https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html 。动效参考：https://www.w3.org/WAI/WCAG22/Understanding/animation-from-interactions.html 。

## 官网研究后的具体页面调整

2026-10-17 16:19：根据用户要求细化修改方式。下列约定用于下一版原型；尚无已实现页面，不构成后台接口或全链路能力已完成。

### 首屏：先看到任务和操作

导航仅保留 co-vibe、工作台、运行记录与实际服务状态。标题、副标题和说明原文保持不变；标题使用紧凑的两级排版，不设置占满一屏的品牌动画区。品牌区下方直接出现任务卡和三步流程概览。

任务卡标题为“业务数据分析”，提供两个版本化示例数据的选择、文件名、数据行数与“预览数据”；只展示接口或实际文件提供的信息。预期成果写“整理后的数据、统计指标、分析报告”。授权用户主按钮为“开始分析”，访客主入口为“查看真实运行”，没有已保存运行时解释当前暂无可查看记录。

三步概览只展示数据整理、统计分析、报告表达的职责。尚未推荐时不放示例 Agent 身份、分数或成功记录。首屏不预先展开候选详情、原始证据流或空白报告面板。

### 执行过程：角色卡替代复杂网络画布

启动后保留输入摘要，横向呈现三个固定角色卡。卡片顺序为角色、实际执行者、状态、当前动作、选择理由入口。理由可显示“从 2 个候选中选出”等有数据支持的内容；无当前动作信息时仅显示已知状态，不自行补写 Agent 行为。

连接处显示可点击的交接状态文字，并提供“查看交接”按钮。点 Agent 或“查看选择理由”使用同一详情面板；点交接打开其产物与接收情况。画面不要求用户拖动画布、缩放或猜测细线的点击范围。

详情先给一句结论，然后呈现相关履历、在线/负载与候选比较，技术值再展开。交接详情先列交付物和接受/退回说明，后列版本、文件与验收证据。视图数据沿用 B 的公共类型；前端仅做信息组织和文字映射。

### 成果与历史：保留上下文

报告可预览时在流程下方显示成果区，明确验收和链上记录状态。只有验证通过的成果标为通过，待确认回执继续显示等待。成果区出现不强制滚动或移动焦点；用户可用“查看报告”主动定位。

运行记录入口打开历史列表，选择运行后在同一工作台查看。当前运行与历史运行均标明 ID、时间和模式。第二轮详情比较角色履历、负载与在线状态的变化，只有数据支持时解释选择原因的改变，不预设执行者更换。

### 尺寸、字体与动效初值

内容最大宽度 1280px，桌面左右留白至少 24px，导航高度约 64px，区块间距 24px，卡片内边距 20px。中文使用系统无衬线字体，正文以 16px 为主，辅助标签不小于 14px；技术标识使用等宽字体并提供完整值查看。所有数值均为原型初值，需在 1440×900 与 1280×800 实测。

详情使用约 400px 宽的侧边抽屉，不压缩三角色卡片；遮罩和关闭按钮行为一致，Esc 可关闭，关闭后焦点返回触发按钮。较窄窗口使用接近全宽的抽屉并保留边距。桌面不增加一块常驻空白侧栏。

按钮颜色过渡以 140ms 为初值，抽屉以 200ms 为初值。交接事件到达时仅短暂高亮连接一次，重复轮询和重开历史不重复播放。执行中的状态图标保持稳定，去掉循环光点、背景粒子及扫描光。减少动态效果设置下移除位移和装饰动画，状态文字完整保留。

### 边界与检查

服务未连接时只影响在线操作，已能读取的历史成果仍可查看。运行创建超时后的查询、重试和断线续接依赖 B 的实际能力，未提供前不伪装已支持。检查主按钮可见性、空记录、长文本、失败、键盘路径、焦点、真实状态与动效一致性。
