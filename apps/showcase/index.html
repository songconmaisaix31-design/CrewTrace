Workflow

从购买服务到可信交付

一次免费 CSV 清洗服务会经过六个阶段。每个阶段都有明确的输入、输出与校验点，失败会停在发生的位置。

  1. 01

    服务发现

    服务目录列出免费与收费项目、价格和可用状态。支付未配置时，免费服务保持可用。

  2. 02

    下单

    买家以协作身份创建订单，提交非敏感 CSV。额度、容量与暂停开关在同一事务内检查。

  3. 03

    Agent 协作

    三个独立 Worker 轮询领取步骤，依次完成源数据检查、去重清洗与证据汇总。

  4. 04

    验证

    契约 schema、SHA-256 内容摘要与确定性 CSV 规则共同判断交付是否通过。

  5. 05

    交付

    买家下载清洗后的 CSV。交付内容与验证记录保持关联，可以按规则重新校验。

  6. 06

    验收与信誉

    买家验收后写入验收记录。经过复核的结果进入信誉事件，未验证的行为保持未记录。

Three Agents

三个角色，各自独立执行

三个 Worker 是独立进程，各自持有协作身份，通过 Runtime 领取任务。失败步骤按租期与重试上限重新派发，避免单点阻塞整条流程。

Inspector

源数据检查

记录输入内容的 SHA-256 摘要与字节数，确认后续步骤处理的是同一份数据。

csv-source-inspection
Cleaner

去重与规范化

按确定性规则清洗记录，处理重复标识与字段格式，输出可复核的 CSV。

csv-data-review · deduplicate
Reporter

证据汇总

输出规则版本、内容摘要与数据行数，形成与交付文件绑定的验证记录。

csv-evidence-report

角色名称用于展示职责划分；实际能力以 Runtime 中登记的步骤与 Worker 身份为准。

Verification

验证与证据，不依赖主观判断

交付是否合格由规则决定。CSV 必须包含 record_id 与 amount_cents 两列，标识不得为空或重复，金额必须是非负整数。任一检查失败都会返回具体问题代码。

  • ✓契约 schema 校验订单、交付与验收数据结构
  • ✓SHA-256 内容摘要绑定输入与交付文件
  • ✓确定性规则版本 csv-ledger-v1
  • ✓执行历史保留角色、步骤与时间顺序
  • ✓失败返回问题列表，便于定位与重试

Reputation

信誉来自已确认的结果

买家验收通过后，系统记录验收决定与评分；经过规则复核的交付会写入信誉事件。没有进入验证流程的角色显示为未记录，不补写、不推断。

信誉的作用是让下一次分工更有依据：历史结果可查询，失败原因可追溯，未验证的行为不会被计入。

买家验收 ACCEPTED / DECLINED
规则复核通过 PASS · DETERMINISTIC_REVIEW
未进入验证的角色 NOT_TRACKED
验收记录 评分与备注按订单保存

当前实现只为经过复核的 CSV 角色写入信誉事件，其余角色不显示为已验证。

Machine Pay

支付能力：接入中，尚未完成生产验证

支付宝支付正在接入与验证。当前部署保持 PAYMENT_MODE=disabled，只开放免费服务，不发起真实资金交易。

能力当前状态说明
免费 CSV 清洗可用本地真实进程运行，用于完整链路验证
收费服务下单未开通支付未配置时返回明确错误，不进入执行
支付宝沙箱接入验证中需要真实商户凭证，尚未完成官方验收
生产支付未验证不宣称已完成真实支付
支付结果未知人工核对未知状态不会自动关闭，需运营核对后关闭

技术路径：预下单、支付凭证校验、结果核对三段式状态机，配合唯一活动支付索引，避免重复支付与并发冲突。

商业化说明：支付目前是接入中的能力展示，不构成已完成的生产支付。
